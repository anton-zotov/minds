# Belief reconciliation

Beliefs describe current subjective understanding; memories retain observed events. Generative appraisal now proposes revisions using existing IDs, replacements that merge redundant beliefs, and retirement of stale beliefs. It is explicitly prompted to update possessions, balances, current offers and deal status rather than copy utterances into new belief objects. Jev judges each entire reconciliation proposal. Acceptance remains a heuristic threshold, not a guarantee of model quality.

An accepted merge revises or adds one belief and retires its specified predecessors in the same atomic operation. Rejection retains all predecessors. A retirement without replacement is judged separately and makes no confidence call. Core operations expose optional `beliefRetirements: { id, evidenceIds, supersededBy: string | null }[]` alongside `beliefUpdates`. A non-null replacement must be updated in that operation. Every retirement must reference an existing belief and the current known observation; duplicate or conflicting changes reject.

Reconciliation applies before emotional appraisal and intention reconsideration. A later failure rolls back the entire event. Memories, initial configuration and historical before/after states remain intact; only current beliefs are retired. Prior intention support references remain historical provenance, and the Mind decides whether to revise its strategy using the reconciled state. Compact and expanded restoration replay these recorded results without AI calls. The optional result field is an additive extension to the current development format; older exports remain supported, but older readers do not understand new retirement operations.

Inspector belief appraisal labels merged and retired statements, transition comparisons show removed beliefs beside revisions, and decision summaries mention retirements. The offline trade fixture updates the initial resource belief after an observed transaction, so Marta ends with a belief about 3 coins and one crate rather than the stale 10-coin state.

[Runtime, boundary and mocked Jev tests](../../packages/minds/test/belief-reconciliation.test.ts) cover stable-ID replacement, retirement, complete merge acceptance/rejection, no-confidence retirement, rollback, idempotency, both appraisal interfaces, replay and tampering. No live reconciliation quality evaluation was performed in this increment. Existing historical turns remain as originally recorded; the new behavior applies when cognition next runs with the updated provider.

Verification: 119 core/host/API tests, 15 browser tests, typecheck and production build passed. Changed snapshots were visually inspected and the browser suite rerun without updates. Independent review found no actionable correctness issue. The built-in reconciliation proposal flow is enabled in sequential Jev appraisal; the legacy combined OpenRouter adapter continues upsert-only generation, while custom combined providers can return retirements.
