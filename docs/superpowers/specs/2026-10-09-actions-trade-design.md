# Actions and two-Mind trade

Implement generic action generation, selection, expression and host execution, plus a runnable buyer/seller conversation. Host owns the world and action capabilities; Minds own goals, intentions, interpretations and action choices. No domain trading concepts in core. Preserve strict observable-only events, evidence-driven completion, compact history and legacy replay. User has authorized implementation without repeat approval.

## Core contract

An ActionOpportunity has id, time (must equal committed Mind time), and capabilities. Each ActionCapability has id, description, targets:string[], parameters:ActionParameter[], expression:'speech'|'none'. ActionParameter has name, type:'string'|'number', description, optional enum:string[], min/max for numbers; all listed parameters required. Capabilities are host permissions, not action instructions. Bound capabilities and candidates; default maximum candidates 6.

ActionCandidate has id, capabilityId, targetId:string|null, intentionId:string|null, objective:string, parameters:Record<string,string|number>. Target must be allowed by capability (null only when targets empty); intention references active intentions only, nullable for direct goal actions. Strictly validate parameters, known IDs and uniqueness.

ActionContext contains mind, memories (latest20) and opportunity; no synthetic world observation. ActionProvider operations: generate(context)->{candidates,metadata}; select({...context,candidates})->{candidateId:string|null,scores:{candidateId,score:number0..1}[],metadata}; express({...context,candidate})->{speech,metadata}. CandidateId null is explicit no action. Expression is requested only for a selected speech capability. Keep objective separate from actual wording. CognitiveProvider.actions optional; failure/absence observable. Built-in generative adapter proposes/expresses, Jev selects with candidate score rubrics and a choice containing no-action.

MindRuntime.planAction(opportunity)->{duplicate,snapshot,records,action:MindAction|null}. MindAction has id, opportunityId, candidate, expression:string|null, status:'proposed'|'submitted'|'executed'|'rejected', reason:string|null. Stable IDs derive from Mind/opportunity, repeat opportunity returns the previous result without inference (including no-action). submitAction(actionId) records proposed->submitted. resolveAction({actionId,status:'executed'|'rejected',reason:string|null}) records host outcome, idempotent identical retries, contradictory outcomes reject. These status receipts are transport bookkeeping, not cognitive completion instructions. Host subsequently delivers observable consequences through ingest. Actions add optional snapshot.actions with durable minimal states. Each operation serialized and atomic; generated decisions/inputs/results inspectable and replayable without inference. New action histories use snapshot/record8 and compact9; preserve expanded1–4/6 and journals5/7 with mixed-history continuation. Never downgrade self-driven/action schemas on later cognition.

## Playbox

Replace the shared-well scenario with two Minds: Marta buys one crate of apples as cheaply as possible, maximum8coins; Ivo sells it for as much as possible, minimum6coins. Their private limits/identity/beliefs are supplied only to their own AI. Buyer starts with10coins, seller owns1crate. Public facts introduce them at the market; no prewritten negotiation dialogue in live mode.

Host capabilities: speak to the other Mind; offer a price; accept the other party's latest open offer. Structured offer/accept parameters validated by host, independent of generated speech. Both parties observe actual utterances and offer/transaction facts; private state is not passed across Minds. Host ledger closes the trade and transfers item/coins exactly once, with validation of balances, possession, offer ownership/recipient/freshness. Wording alone cannot execute a deal. Consequences are observations interpreted by each Mind.

One step schedules the next alternating actor. Bounded run performs at most12turns and stops on a completed transaction, provider/delivery failure or exhaustion. A host rejection is observed and later turns can continue; no recursive auto action in ingest. Fixture demonstrates offline offer/counteroffer/accept negotiation using only the acting Mind's context. Live models generate their own dialogue. Failures expose retryable stage, preserve pending selected action/outcomes and cannot duplicate submission/utterances/transfer or deliver self-speech twice. Reset creates a fresh world. Scenario export includes world/offers/transcript and both restorable Mind journals.

UI retains minimal existing design: trade state and transcript, step/run controls, two selectable Minds and existing diagnostics. Show proposal, selection, speech, execution status/evidence. Keep clean observation injection recipient controls. Update screenshots/tests and CAPABILITIES. Offline test/mocked providers only; no paid live inference required. Do not claim model-quality evaluation from fixtures.

Validated generation/selection stages survive later-stage failure in one transient pending cache. Any committed state change invalidates it; successful plans remain durable in the journal. Restart restoration does not preserve uncommitted provider work.
